# 닛팅 상태 (2026-09-17, 웹앱 전환 후)

## 방향 전환 (2026-09-17)

**iOS·Android 네이티브 앱을 접고 웹앱 하나로 간다.**

- 이유: 혼자 개발한다. 네이티브는 플랫폼별 영상 인코더(Swift·Kotlin), 실기기 빌드·재설치, 스토어 심사를 두 벌 유지해야 한다
- 받아들인 비용: 사진첩에 직접 저장 불가 → **공유 창에서 "이미지 저장"을 한 번 더 누른다**. iPhone 촬영 리마인더 알림은 홈 화면에 추가한 경우만 가능
- 네이티브 코드는 PR #1 병합 커밋(`a26640a`)까지 git 기록에 있다

1. Supabase 프로젝트 → `supabase/migrations/`의 0001 → 0004를 순서대로 SQL Editor에서 실행 (**실서버 적용 완료 2026-09-17**)
2. Authentication → Email → **Confirm email 끄기** (도그푸딩 중, 적용 완료)
3. 루트 `.env` (`.env.example` 참고, 로컬 설정 완료)
4. HTTPS 배포: **https://knitting-pied.vercel.app** (Vercel `knitting` 프로젝트, 2026-09-17). 환경변수 `EXPO_PUBLIC_SUPABASE_*`는 Vercel에 등록됨

## 확인한 것

데스크톱 Chromium(가짜 카메라) + 로컬 Supabase 자동 검증:

- 가입 → 편물 → 촬영 3장(1440×1440 저장) → 목록 → 영상(ffprobe: h264 High 1080×1080 20프레임)
- 앨범 가져오기(EXIF 회전 6 정상) → 공개 범위 → 삭제
- 사진 1100장 편물: 목록 사진 수·타임라인 카운터, 서명 URL 재사용, 서버 함수로 공개 범위·삭제
- 결과 사진: 1장일 때 전후·3분할 비활성, 기본 종류 자동 선택, 세 종류 1080×1080 JPEG, 한글 라벨
- 저장: 공유 창이 있는 브라우저를 흉내 내 결과 사진 JPEG·영상 MP4가 공유 창으로 넘어감. 없는 브라우저는 파일 내려받기
- VS Code 크기(760×620)·데스크톱(1280×800)에서 버튼이 화면 안
- RLS·서버 함수 SQL 19건 ALL PASS, 단위 테스트 33건, 프로덕션 웹 빌드

실기기 (하은, iPhone Safari, 운영 주소, 2026-09-17):

- 가입 → 편물 → 카메라 촬영 → 결과 사진 → 공유 창 "이미지 저장" → 사진 앱에 저장됨
- 영상 만들기(WebCodecs) → 공유 창 "비디오 저장" → 사진 앱에 저장됨

## 확인 못 함

- iPhone Safari: 앨범에서 가져오기(EXIF), 저장된 사진·영상 해상도, 사진이 많을 때 영상 속도, 홈 화면 추가
- Android Chrome 전부
- 사진 1000장 넘는 편물의 영상 만들기 속도 (사진을 한 장씩 받는다)
