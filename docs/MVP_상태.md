# 닛팅 MVP 상태 (2026-09-07)

## 되는 것

| 영역 | 내용 |
|---|---|
| 편물 | 만들기(이름·시작일·공개범위), 목록, 삭제, 공개범위 변경 |
| 촬영 | 1:1 고정, 고스트 레이어(끔/30/60), 3×3 격자, 앨범에서 가져오기, 권한 거부 안내 |
| 저장 | EXIF 정규화 → 중앙 정사각 크롭 → 1440 리사이즈 → 400 썸네일 → 파일 → DB |
| 타임라인 | 정사각 사진, 스크러버(처음/마지막), 날짜·카운터 |
| 영상 | 기기 안에서 H.264 MP4 생성, 진행률, 앨범 저장, 공유 |
| 계정 | 이메일 가입·로그인, 온보딩(아이디·표시이름·비공개), 로그인 없이 쓰기 |
| 동기화 | 로컬 우선 push/pull. 기기를 바꿔도 편물과 사진이 따라옴 |
| 피드 | 팔로잉 피드, 탐색(최신/인기), 사용자 검색 |
| 소셜 | 팔로우(비공개는 승인 대기), 요청 승인·거절, 좋아요, 댓글 |
| 안전 | 신고(사유 5종), 차단(양방향), 차단 목록, 신고 3회 자동 숨김 |

## 켜기 전에 사람이 해야 할 것

1. Supabase 프로젝트 생성 → `supabase/migrations/`의 0001 → 0002 → 0003 → 0004를 순서대로 SQL Editor에 붙여 실행
2. Authentication → Providers → Email → **Confirm email 끄기** (도그푸딩 중)
3. 루트에 `.env` 만들기 (`.env.example` 참고). 넣지 않으면 앱은 로컬 전용으로 동작한다
4. `npx expo run:ios --device` 로 재빌드 (네이티브 모듈이 늘었다)

## 확인한 것 / 확인 못 한 것

- 확인: TypeScript strict 통과, 단위 테스트 20건, iOS/Android 네이티브 컴파일, JS 번들 3.6MB
- **확인 못 함**: 실기기에서의 영상 인코딩 속도·색상, 두 기기 사이 동기화, RLS 조합 10종.
  RLS는 눈으로 검증할 수 없다 — 설계도 4장 검증 매트릭스를 SQL 테스트로 고정할 것

## 웹 버전 (2026-09-17)

같은 코드베이스에 웹 타깃을 추가했다. 웹은 로그인 필수, 사진은 Supabase에만 저장한다.

| 영역 | 웹 |
|---|---|
| 편물 | 만들기, 목록(사진 수·표지), 공개 범위 변경, 삭제 |
| 촬영 | 브라우저 카메라(높은 해상도 요청), 겹치기·격자, 앨범(파일)에서 가져오기 |
| 저장 | 정사각 크롭 → 1440 → 400 썸네일 → Storage 업로드 → DB INSERT (실패 시 업로드 파일 삭제) |
| 영상 | WebCodecs H.264 MP4 (High 1080×1080 8fps), 파일로 저장, Web Share 공유 |
| 대화상자 | 브라우저 alert/confirm/prompt (선택지가 여럿이면 번호 입력) |

- 확인: 로컬 Supabase + Chromium(가짜 카메라)으로 가입 → 온보딩 → 편물 → 촬영 3장 → 목록 → 영상(ffprobe: h264 High 1080×1080, 20프레임) → 앨범 가져오기(EXIF 회전 6 정상) → 공개 범위 → 삭제. 웹·iOS 번들 export 통과
- **확인 못 함**: iPhone Safari·Android Chrome 실기기(카메라 해상도, WebCodecs, 공유 시트)
- 넓은·낮은 창(데스크톱 1280×800, VS Code 760×620): 폰 너비 한 칸 + 사진을 창 높이에 맞춤. 타임라인 버튼·촬영 셔터가 화면 안에 들어오는 것 확인
- 한계 수정 (2026-09-17, `0004`): 편물 목록 집계를 서버 함수로(1000행 제한 해소) · 사진 조회를 1000장씩 나눠 끝까지 · 서명 URL을 만료 15분 전까지 재사용 · 편물 삭제·공개 범위 변경을 서버 함수 한 트랜잭션으로. E2E로 사진 1100장 편물의 목록 수·타임라인·같은 URL 재사용·삭제를 확인
- 남은 한계: 화면을 다시 불러오지 않은 채 한 탭을 1시간 넘게 보면 사진 주소가 만료된다 (탭 전환·화면 이동 시 새로 받음) · 1000장 넘는 편물의 영상은 사진을 한 장씩 받으므로 오래 걸린다
- 켜기: `.env` 설정 후 `npm run web`. 배포: `npx expo export -p web` → `dist/`를 정적 호스팅 (SPA 리라이트 + HTTPS)

### 웹 작업 중 찾은 서버 버그 (앱에도 영향)

- `0002`: 사진 INSERT가 "infinite recursion detected in policy for relation posts"로 실패 → **앱의 사진 동기화도 실패했을 것**
- `0003`: 사진 soft delete가 403으로 실패 (UPDATE 결과가 SELECT 정책에 걸림) → **앱의 삭제 동기화도 실패했을 것**
- `supabase/tests/rls_matrix.sql`에 쓰기 케이스 4건 추가(11~14). 수정 전 실패, 수정 후 14건 ALL PASS

## 결과 사진 (2026-09-17)

타임라인 → **결과 사진**. 설계도 6장 스펙대로 기기 안에서 합성한다 (서버 왕복 없음).

| 종류 | 구성 | 필요한 사진 |
|---|---|---|
| 전체 | 가장 최근 사진 + 편물 이름 · 며칠째 · 날짜 | 1장 |
| 전후 | 첫 사진 \| 최근 사진, 칸마다 "N일째" | 2장 |
| 3분할 | 첫 \| 기간의 시간상 한가운데 \| 최근, 칸마다 "N일째" | 3장 |

- 출력 1080×1080 JPEG q90. 앱은 Skia 오프스크린(`composeResult.ts`) → 앨범 저장·공유, 웹은 Canvas(`composeResult.web.ts`) → 파일 저장·Web Share
- 장면 계산은 `resultPlan.ts` 순수 함수 하나를 두 플랫폼이 공유한다 (단위 테스트 13건)
- 확인(웹): 사진 1장일 때 전후·3분할 비활성, 기본 종류 자동 선택, 세 종류 모두 1080×1080 JPEG 내려받기, 한글 라벨 렌더, VS Code 크기에서 버튼이 화면 안
- **확인 못 함(앱)**: 실기기·시뮬레이터에서 Skia 합성·한글 폰트 대체·앨범 저장. 타입 검사와 iOS 번들 빌드만 통과
