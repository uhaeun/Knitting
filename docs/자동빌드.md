# 자동 검사와 앱 빌드

2026-09-29 갱신. 실행 정의는 `.github/workflows/`가 기준이다.

| 워크플로 | 실행 시점 | 확인하는 것 |
|---|---|---|
| `tests.yml` | PR, main push, 수동 | lint(경고 0), TypeScript, Jest |
| `e2e.yml` | main push, 수동 | 임시 로컬 Supabase·마이그레이션·RLS SQL·웹 E2E 전체 |
| `android-build.yml` | main push, 수동 | 웹 산출물을 포함한 Android debug APK |
| `ios-build.yml` | iOS·Capacitor·의존성 관련 main 변경, 수동 | 서명 없는 시뮬레이터 빌드 |

E2E도 GitHub Linux 러너에서 실행한다. 운영 DB에 시험 데이터를 만들지 않는다. SQL assertion 실패나 E2E 비정상 종료·시간 초과는 실패다. 전체 목록은 `scripts/e2e/run-all.mjs`에 있으며 현재 30개다.

## 출시 후보

```bash
gh workflow run e2e.yml --ref <검사할-브랜치>
gh run list --branch <검사할-브랜치>
```

통과한 커밋을 기록한다. 실기기 QA에도 같은 커밋·배포 URL 또는 APK 출처를 남긴다. 별도 브랜치 검사 결과와 main 검사 결과를 구분한다.

## Android APK

[Actions](https://github.com/uhaeun/Knitting/actions)의 `Android APK 빌드`에서 `knitting-android-debug` artifact를 받는다. 현재 보관 기간은 **30일**이다.

이 APK는 웹 파일을 앱 안에 포함한다. 변경을 폰에서 보려면 새 APK를 설치해야 한다. `scripts/app-dev.sh live-android`로 만든 개발용 앱은 운영 웹을 읽으므로 동작 방식이 다르다.

## 환경변수

앱 빌드는 Actions secrets의 `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`를 사용한다. 웹 배포는 Vercel 환경변수를 별도로 사용한다.

클라이언트에는 anon 공개 키만 포함한다. 운영 service-role 키를 앱·웹 빌드에 넣지 않는다. E2E의 service-role 키는 그 실행에서 띄운 로컬 시험 서버 값이다.

## iOS

CI는 `iphonesimulator` 대상으로 빌드한다. `.ipa` 배포·TestFlight·스토어 제출은 하지 않는다. CI 초록불만으로 실제 iPhone 카메라·사진첩·알림 동작을 보증할 수 없다.

개발용 `live-ios`와 최종 설치본 QA를 구분한다. 서명·배포 계정 준비는 실제 제출 시점에 확인하고 포트폴리오에는 완료한 범위만 적는다.
