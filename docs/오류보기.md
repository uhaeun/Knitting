# 오류 확인하는 법

2026-09-20 작성 · 앱에서 터진 오류는 **우리 Supabase의 `client_errors` 표**에 모인다. 바깥 서비스(Sentry 등)에 보내지 않는다.

## 어디서 보나

https://supabase.com/dashboard/project/nnclnleuozwjtwgvtgvn/editor 에서 `client_errors` 표를 연다.
정렬은 `created_at` 내림차순으로 두면 최근 것이 위로 온다.

| 칸 | 뜻 |
|---|---|
| message | 오류 문구 (최대 500자) |
| stack | 어느 코드에서 터졌는지 (최대 4000자) |
| where_at | 그때 보던 화면 주소 (`/projects` 등) |
| agent | 브라우저·기기 |
| app | `web` / `ios` / `android` (앱으로 감싼 상태면 기기 이름) |
| user_id | 로그인 상태였으면 그 사람, 아니면 빈칸 |

## 자주 보는 것들

```sql
-- 최근 하루, 많이 난 순서
select message, count(*), max(created_at) as 마지막
from client_errors
where created_at > now() - interval '1 day'
group by message
order by count(*) desc;

-- 특정 화면에서만 나는 오류
select * from client_errors where where_at = '/capture' order by created_at desc limit 20;

-- 오래된 기록 지우기 (한 달 지난 것)
delete from client_errors where created_at < now() - interval '30 days';
```

## 무엇이 모이나

- 어디서도 잡지 못한 오류 (`window.onerror`, 처리되지 않은 약속 실패)
- 서버와 주고받다 실패한 것 (TanStack Query의 query·mutation 실패)

같은 문구는 **1분에 한 번만** 쌓인다 (한 사람이 같은 오류로 수백 줄을 만들지 않게).

## 무엇이 안 모이나

- 사진·영상 내용, 메모, 이메일 같은 개인 자료는 보내지 않는다
- 앱에서는 이 표를 **읽을 수 없다** (읽기 정책이 없다). 대시보드에서만 본다

## 지금 상태 확인

오류가 실제로 쌓이는지 보려면 `scripts/e2e/error-report.mjs`를 돌린다 (로컬 Supabase 기준).
