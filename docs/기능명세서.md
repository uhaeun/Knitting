# 닛팅 기능 명세서 (QA 기준)

2026-09-18 기준. 배포 주소 https://knitting-pied.vercel.app · 저장소 `main` (0e58a54).

코드에서 확인한 동작만 적는다. 화면에 보이는 문구는 코드와 글자 그대로 같다.
**웹 전용 앱**(react-native-web)이고 주 사용 환경은 iPhone Safari다.

## 읽는 법

- **조건 → 결과** 형식. QA는 조건을 만들고 결과를 확인한다.
- 문구는 따옴표 안이 화면에 나오는 그대로다.
- "없음"으로 적은 것은 만들지 않은 기능이다. 버그가 아니다.

## 1. 가입 · 로그인

화면: `src/app/(auth)/sign-in.tsx`

| 항목 | 규칙 |
|---|---|
| 입력 | 이메일, 비밀번호(**8자 이상**) |
| 버튼 활성 | 이메일에 `@`가 있고 비밀번호가 8자 이상일 때만 (가입은 약관 동의까지) |
| 버튼 문구 | "로그인" / "가입하기", 처리 중에는 "잠시만요…" |
| 모드 전환 | "계정이 없어요, 가입할게요" ↔ "이미 계정이 있어요" |
| 비밀번호 찾기 | 로그인 모드에서만 "비밀번호를 잊었어요" |

오류 문구
- 비밀번호·이메일 틀림: "이메일 또는 비밀번호가 맞지 않아요"
- 짧은 비밀번호: "비밀번호는 8자 이상" (서버 설정도 8자로 맞춰야 한다)
- 이미 가입된 이메일: "이미 가입된 이메일이에요. 로그인해 주세요"
- 너무 잦은 시도: "잠시 후 다시 시도해 주세요"
- 그 밖의 오류는 서버 영어 문구가 그대로 보인다 **(알려진 한계)**

### 1-1. 비밀번호 찾기

화면: `src/app/(auth)/forgot-password.tsx`(메일 요청), `src/app/reset-password.tsx`(새 비밀번호)

- 메일 주소를 넣고 "재설정 메일 보내기" → "메일을 보냈어요. 링크를 누르면 새 비밀번호를 정할 수 있어요. 10분 안에 눌러 주세요."
- **가입 안 된 주소여도 똑같이 보냈다고 나온다.** 계정이 있는지 알려주지 않기 위해서다 (Supabase 방침)
- 메일 링크로 들어오면 주소의 토큰으로 로그인되고, 주소창은 곧바로 비워진다. 비밀번호를 바꾸기 전에는 다른 화면으로 나갈 수 없다
- 새 비밀번호는 6자 이상 + 한 번 더 확인. 다르면 "두 번 입력한 비밀번호가 달라요"
- 바꾸면 "비밀번호를 바꿨어요" 뒤 편물 목록으로. 옛 비밀번호로는 더 이상 로그인되지 않는다
- 링크가 만료·재사용이면 "링크를 쓸 수 없어요 / 링크가 만료됐어요. 다시 보내 주세요." + "다시 보내기"
- "나중에 할게요"를 누르면 로그아웃하고 로그인 화면으로
- ⚠️ 실제 서버에서는 Supabase 대시보드의 Redirect URL 목록에 배포 주소가 있어야 링크가 동작한다

### 1-2. 약관 동의

- 가입 모드에서만 "약관과 개인정보처리방침에 동의합니다" 체크가 나온다. **체크 전에는 "가입하기"가 꺼져 있다**
- 체크 아래 "이용약관 보기", "개인정보처리방침 보기" → `src/app/legal/[doc].tsx`. **로그인 없이도 읽을 수 있다**
- 동의한 판(`LEGAL_VERSION`)은 프로필을 만들 때 `profiles.eula_version`에 저장된다
- 설정 → "약관과 문의"에서도 두 문서를 볼 수 있다
- 본문은 `src/features/legal/policy.ts` 한 곳에 있다. 고치면 `LEGAL_VERSION`을 올린다

### 1-3. 이메일 인증

- 가입하면 바로 들어가지 않고 "{메일 주소}로 확인 메일을 보냈어요. 메일의 링크를 누르면 가입이 끝나요."가 뜬다
- "메일 다시 보내기" 버튼이 있다. 너무 자주 누르면 "잠시 후 다시 시도해 주세요"
- 확인 전에 로그인하면 "메일의 확인 링크를 먼저 눌러 주세요"
- 메일 링크를 누르면 로그인된 상태로 첫 설정(온보딩)으로 간다. 주소의 토큰은 바로 지워진다
- **켜고 끄기는 Supabase 대시보드 Authentication → Providers → Email → Confirm email.** 꺼져 있으면 가입 즉시 들어간다 (코드는 둘 다 지원)
- 이미 가입해 둔 계정은 영향을 받지 않는다

### 1-4. 카카오·구글 로그인

- 로그인 화면 아래 "카카오로 계속하기", "구글로 계속하기"
- **서버에서 켜 둔 방법만 버튼이 보인다.** 대시보드에서 켜면 앱을 고치지 않아도 나타난다
- 그쪽 화면에 다녀오면 로그인된 상태로 돌아온다. 프로필이 없으면 첫 설정으로 간다
- 네이버는 Supabase가 기본 지원하지 않는다 (**만들지 않음**)

**계정**
- 애플 로그인 (개발자 계정이 있어야 한다)
Supabase에서 이메일 확인이 켜져 있으면 가입 후 "가입은 됐지만 로그인되지 않았어요…"가 나온다. 개발용 문구다.

서버 주소가 설정되지 않으면 앱 전체가 "서버 설정이 필요해요" 화면으로 막힌다.

## 2. 첫 설정 (온보딩)

화면: `src/app/(auth)/onboarding.tsx` · 로그인했지만 프로필이 없을 때만 나온다.

| 입력 | 규칙 | 오류 문구 |
|---|---|---|
| 아이디 | 영문 소문자·숫자·밑줄 3~20자. 입력하면 자동으로 소문자로 바뀌고 다른 글자는 지워진다 | "영문 소문자·숫자·밑줄 3~20자" |
| 표시 이름 | 1~30자 | "1~30자" |
| 비공개 계정 | 기본 꺼짐. 설명 "켜면 승인한 사람만 내 편물을 볼 수 있어요" | |

- 이미 쓰는 아이디면 "이미 쓰고 있는 아이디예요"
- 버튼 "시작하기", 처리 중 "만드는 중…"
- "다른 계정으로 로그인"은 확인 창 없이 바로 로그아웃한다
- 표시 이름과 소개는 나중에 "나" 탭 → 프로필 편집에서 바꿀 수 있다

프로필 사진
- "나" 탭 → 프로필 편집 → "사진 넣기". 앨범에서 고르면 가운데를 정사각으로 잘라 400px JPEG로 올린다
- 올린 뒤에는 "사진 바꾸기"와 "사진 지우기"가 보인다. 지우면 이름 첫 글자 동그라미로 돌아간다
- 피드, 탐색, 프로필, 팔로우 요청, 차단 목록에 모두 같은 동그라미로 나온다
- 파일은 `avatars` **공개 버킷**에 있다. 남의 사진도 목록에서 보여야 해서 서명 URL을 쓰지 않는다 (마이그레이션 0007)

없음: 사진 각도 조절·필터.

## 3. 편물 목록과 만들기

화면: `src/app/(tabs)/projects.tsx`, `src/features/project/CreateProjectSheet.tsx`

- 목록 순서: 최근에 만든 편물이 위
- 항목에 보이는 것: 이름, "N일째 · 9월 17일 시작", 사진 수, 표지 사진
- 편물이 없을 때: "첫 편물을 만들어 보세요" + "편물 만들기"

만들기 시트
- 이름 1~50자, 넘으면 입력이 막힌다. 비면 "만들기" 버튼이 꺼져 있다
- 시작일을 고를 수 있다 (기본 오늘, 오늘보다 뒤는 못 고른다). 지난 날짜를 고르면 "N월 N일부터 뜬 편물이에요"
- 시작일은 **오늘 고정** (날짜 선택 없음)
- 공개 범위 3가지, 기본은 "나만". 설명 문구는 **고른 것 하나만** 보인다
  - 나만: "기기와 내 계정에만 남습니다"
  - 팔로워: "승인한 사람에게만 보여요"
  - 전체: "탐색 탭에 올라갑니다"
- 실패하면 "저장하지 못했어요"

## 4. 편물 화면 (타임라인)

화면: `src/app/project/[id].tsx`

- "⋯" 메뉴: "이 기록의 날짜 고치기", "지금 보는 기록 지우기"(둘 다 기록이 있을 때), "이름 바꾸기", "날짜 바꾸기 · 완성 표시", "공개 범위 바꾸기", "편물 삭제"
- 기록 날짜 고치기: 날짜만 바꾸고 시각은 그대로 둔다. 타임라인·결과물 순서가 함께 바뀐다
- 기록 순서 바꾸기: ⋯ → "기록 순서 바꾸기"를 켜면 사진 아래 "← 앞으로 / 뒤로 → / 끝내기"가 나온다. 이웃한 기록과 촬영 시각을 맞바꾼다 (마이그레이션 0011)
- 지운 편물과 기록은 **설정 → 휴지통**에서 되돌릴 수 있다. 편물을 되돌리면 함께 지워진 기록도 같이 살아난다 (마이그레이션 0008)
- 날짜 시트: 시작일 고치기, "완성했어요"(오늘로 완성일 지정) ↔ "다시 진행 중으로". 완성일이 시작일보다 앞이면 저장이 막힌다
- 완성한 편물은 목록 카드 이름 옆에 "완성" 표시가 붙고, 편물 화면 부제에 완성일이 나온다
- 이름 바꾸기: 지금 이름이 채워진 입력창. 1~50자, 비었거나 그대로면 "저장"이 꺼져 있다. 피드·목록의 이름도 같이 바뀐다
- 기록 지우기: "N번째 기록을 지울까요?" / "{촬영 일시}에 찍은 사진(영상)이에요. 목록과 결과물에서 빠집니다." → 앞 장으로 이동
- 공개 범위를 바꾸면 **이미 올린 사진과 영상의 공개 범위까지 전부 바뀐다.** 따로 확인 창은 없다 **(QA 중점)**
- 삭제: "편물을 삭제할까요?" / "목록에서 사라집니다. 사진 파일은 남습니다." → 목록에서 사라지고 이전 화면으로 돌아간다
- 삭제된 편물 주소로 들어가면 "편물을 찾을 수 없어요"
- 기록이 없으면 "아직 사진이 없어요" + "첫 장을 찍으면 그게 앞으로의 기준 각도가 됩니다."

없음: 삭제 되돌리기.

## 5. 피드 · 탐색 · 프로필

한 번에 불러오는 개수는 12개, 아래로 내리면 이어서 불러온다.

**피드** (`src/app/(tabs)/index.tsx`)
- 내가 팔로우하고 **승인된** 사람의 기록만, 최신순
- 팔로우 요청이 있으면 "팔로우 요청 N" 표시
- 비어 있으면 "아직 볼 게 없어요" + "탐색 열기"
- 각 카드: 사진, 좋아요, 댓글 수, "⋯"(신고하기 / 이 사람 차단)

**탐색** (`src/app/(tabs)/explore.tsx`)
- 검색은 2글자부터. **사람 · 편물 이름 · 기록 메모**를 한 번에 찾아 "사람 / 편물 / 메모"로 나눠 보여 준다
- `#태그`로 적으면 메모 안의 해시태그를 찾는다 (메모에 그대로 적힌 글자를 찾는 방식)
- 공개된 기록이 있는 편물만 걸린다. 남의 비공개 편물은 검색에도 안 나온다
- 전체 공개 기록만 3칸 격자로 보여 준다
- "최신"과 "인기" 모두 12개씩 이어서 불러온다. 인기는 좋아요 수가 같은 글이 여럿이라 "좋아요 수 + 올린 시각"을 함께 기준으로 이어 받는다 (중간에 좋아요가 눌려도 건너뛰거나 겹치지 않는다)

**프로필** (`src/app/(tabs)/me.tsx`, `src/app/user/[username].tsx`)
- 사진 수·팔로워·팔로잉, 내 기록 3칸 격자, 영상에는 ▶ 표시
- 팔로우 버튼: "팔로우" → 비공개 계정이면 "요청됨", 공개 계정이면 바로 "팔로잉"
- 비공개 계정은 **프로필 자체가 안 보인다.** 모르는 사람이 주소로 들어가면 "없는 사용자예요"가 나온다 **(정상 동작, 헷갈리기 쉬움)**
- 차단: "{이름} 님을 차단할까요?" / "서로의 게시물이 보이지 않고 팔로우가 해제됩니다." → 팔로우 관계도 함께 끊긴다

## 5-1. 소식 (알림)

화면: `src/app/notifications.tsx` · 피드 탭 오른쪽 위 "소식" 버튼 (안 읽은 수가 함께 나온다, 30초마다 갱신)

- 쌓이는 것: 내 기록에 달린 좋아요·댓글, 나를 팔로우, 팔로우 요청
- **서버가 직접 쌓는다** (마이그레이션 0009의 트리거). 앱은 넣지 못하고 읽고 읽음 표시만 한다
- 내가 한 일은 나에게 쌓이지 않는다. 차단한 사이도 쌓이지 않는다
- 좋아요를 취소하면 그 소식도 사라진다
- 소식을 누르면 그 게시물(또는 요청 화면, 프로필)로 간다
- 화면을 열면 모두 읽음 처리된다. 안 읽은 줄은 배경이 연한 주황

## 6. 게시물 상세 · 댓글 · 신고

화면: `src/app/post/[id].tsx`, `src/features/social/ReportSheet.tsx`

- 볼 수 없는 기록(삭제·숨김·차단·권한 없음)은 모두 같은 문구: "게시물을 볼 수 없어요" / "삭제되었거나 볼 권한이 없습니다."
- 좋아요 숫자를 누르면 누가 눌렀는지 목록이 뜬다 (0이면 눌리지 않는다). 이름을 누르면 그 사람 프로필로
- 댓글 1~300자, "댓글 달기" 입력 후 "등록". 없으면 "첫 댓글을 남겨 보세요"
- 댓글 삭제는 내가 쓴 댓글 또는 내 기록의 댓글만. **고치기는 내가 쓴 댓글만** (고치면 "수정됨"이 붙는다)
- 원 댓글의 "답글"을 누르면 입력칸 위에 "○○님에게 답글"이 뜨고, 답글은 원 댓글 아래에 들여써서 붙는다
- **답글에는 답글을 달 수 없다** (한 단계까지, 마이그레이션 0010의 트리거가 막는다)
- 답글은 게시물 주인과 원 댓글 글쓴이 모두에게 소식이 간다
- 내 기록이면 "⋯" → "이 사진(영상) 지우기" → "이 사진을 지울까요?" / "편물 기록과 결과물에서도 빠집니다. 되돌릴 수 없어요." → 이전 화면으로. 남의 기록이면 "⋯"가 신고
- 피드 카드 "⋯"도 내 기록이면 같은 지우기가 나온다
- 신고 사유 5가지: 부적절한 사진 / 괴롭힘 또는 혐오 / 스팸 또는 광고 / 내 저작물 도용 / 기타
- 신고 후: "신고했어요" / "검토 후 조치합니다. 같은 게시물이 3번 신고되면 자동으로 숨겨져요."
- 같은 대상을 또 신고하면 "이미 신고하셨어요"
- **신고 3번이면 자동으로 숨겨진다.** 숨겨진 기록은 남에게 안 보이고, 상세 화면에서는 위의 "볼 수 없어요" 문구가 나온다

## 7. 설정

화면: `src/app/settings/*`

- 계정: 아이디·이메일은 보기만, 비공개 계정 켜고 끄기
- 팔로우 요청: "승인" / "거절", 둘 다 확인 창 없음. 없으면 "새 요청이 없어요"
- 차단한 사람: "차단 해제", 확인 창 없음
- 로그아웃: 확인 창 없이 바로
- 계정 삭제: 설정 → "계정 삭제". 아이디를 그대로 적어야 "계정 지우기"가 켜진다. 저장소 파일을 먼저 지우고 서버 함수 `delete_my_account()`가 `auth.users`를 지운다. 프로필·편물·기록·댓글·팔로우가 함께 사라지고 로그인 화면으로 간다. **되돌릴 수 없다**

## 8. 누가 무엇을 볼 수 있나 (서버 규칙)

앱 화면이 아니라 데이터베이스에서 막는다. 화면을 우회해도 같은 결과다.

| 대상 | 볼 수 있는 사람 |
|---|---|
| 기록(전체 공개) | 모두. 단 서로 차단한 사이는 제외 |
| 기록(팔로워) | 승인된 팔로워만. 요청 중인 사람은 못 본다 |
| 기록(나만) | 본인만 |
| 비공개 프로필 | 본인과 승인된 팔로워만 |
| 사진·영상 파일 | 그 파일을 쓰는 기록이 보일 때만. 남의 폴더 파일을 내 기록에 적어도 안 열린다 |
| 삭제한 기록 | 아무에게도 안 보인다. 파일은 서버에 남는다 |

- 차단하면 팔로우가 양쪽 다 끊긴다. 차단당한 사람은 자신이 차단됐는지 알 수 없다
- 좋아요·댓글 수는 서버가 세고, 댓글을 지우면 수도 줄어든다

## 9. 촬영 화면

화면: `src/app/capture/[projectId].tsx`, `src/features/capture/*`

**공통**
- 제목: "{편물 이름} · 첫 장" 또는 "{편물 이름} · N일째"
- 첫 촬영에는 겹치기·격자 대신 안내가 나온다: "편물을 화면 중앙에, 배경은 단색으로 두세요." / "이 첫 장이 앞으로의 기준 각도가 됩니다."
- 둘째 장부터 직전 사진이 겹쳐 보인다. 진하기 "끔 / 30% / 60%", 격자 켜고 끄기
- **겹치기·격자·사진/영상 선택은 저장되지 않는다.** 앱을 다시 열면 기본값(30%, 격자 켬, 사진)으로 돌아간다 **(알려진 한계)**
- 카메라를 못 열면 "카메라를 열지 못했어요…" 문구와 함께 앨범 버튼만 쓸 수 있다
- 권한이 없으면 "카메라를 쓸 수 없어요" 화면. 버튼은 "권한 허용"/"다시 시도", "앨범에서 가져오기", "닫기"

**사진 모드**
- 셔터 한 번 = 한 장. 저장 중에는 "저장 중"
- 앨범에서 사진 가져오기 가능. **한 번에 20장까지** 고를 수 있고 고른 순서대로 저장된다 ("N장째 저장 중" 표시)
- 여러 장을 가져오면 파일에 적힌 시각이 촬영 시각이 된다 (없으면 지금 시각). 중간에 실패하면 "N장만 저장했어요"
- 실패하면 "저장하지 못했어요" + 다시 시도

**영상 모드**
- 브라우저가 녹화나 인코딩을 못 하면 [영상] 선택이 꺼져 있다
- 셔터 한 번 = 녹화 시작, 다시 = 끝. 녹화 중에는 `● 0:03 / 0:05`
- **5초에 자동으로 멈춘다.** 이때 안내 문구는 나오지 않는다
- **1초 미만은 저장하지 않고** "1초 이상 찍어 주세요"
- 녹화 중에는 사진/영상 전환과 앨범 가져오기가 막힌다
- 앨범 영상이 5초를 넘으면 앞 5초만 쓰고 "앞 5초만 저장했어요" / "영상 기록은 5초까지예요."
- 영상도 **한 번에 5편까지** 고를 수 있다. 편마다 변환·업로드라 "N편째 변환 중 · 전부 M편"으로 알려 준다
  - 자동 정지로 5.0~5.5초가 된 경우에는 이 안내가 나오지 않는다
- 앨범 영상이 1초 미만이면 "1초 이상인 영상을 골라 주세요" (다시 시도 없이 닫기만)
- 저장 진행: "변환 중 N%" → "올리는 중"
- **녹화 중 다른 앱으로 전환하거나 전화가 오면** 거기까지를 저장한다

## 10. 저장되는 형식

| 무엇 | 규격 |
|---|---|
| 사진 | 정사각 자르기 → 최대 1440px JPEG |
| 썸네일 | 400px JPEG |
| 영상 | 1080×1080, H.264 MP4, **소리 없음**, 30fps, 4Mbps, 최대 5초 |
| 영상의 대표 사진 | 영상 첫 장면으로 사진·썸네일을 함께 만든다 |

- 올리는 순서: 영상 → 대표 사진 → 썸네일 → 기록 저장
- **중간에 실패하면 올라간 파일을 모두 지운다.** 반쯤 남지 않는다
- 다시 시도하면 촬영은 반복하지 않고 처리만 다시 한다
- 저장소 한 파일 최대 10MB, 사진(JPEG)과 영상(MP4)만 허용
- 영상 길이는 서버에서 1~5500ms만 허용한다 (앱은 5000ms까지 만든다)

## 11. 타임라인에서 보기

- 영상 기록은 소리 없이 자동 반복 재생되고, 왼쪽 아래에 `▶ 0:04` 배지가 붙는다
- 영상을 못 불러오면 대표 사진과 함께 "영상을 불러오지 못했어요"가 위쪽에 나온다
- **성장 영상을 만드는 동안에는 재생을 멈추고 대표 사진만 보여 준다** (iPhone에서 영상 처리가 겹치지 않게)
- 아래 슬라이더로 날짜를 넘긴다. "처음"/"마지막" 버튼이 있다
- 새로 찍으면 마지막 장으로 자동으로 이동한다
- 버튼: "사진 찍기", "결과 사진", "영상 만들기"
  - 기록이 2개 미만이면 "영상 (2개부터)"으로 꺼져 있다

## 12. 결과 사진

화면: `src/app/result/[projectId].tsx`

| 종류 | 필요한 기록 | 고르는 기준 |
|---|---|---|
| 전체 | 1개 | 가장 최근 1개 |
| 전후 | 2개 | 첫 기록과 가장 최근 기록 |
| 3분할 | 3개 | 첫 기록, 기간의 한가운데, 가장 최근. 가로 띠 셋을 위아래로 쌓는다. 비율은 4:5·9:16만 (기본 9:16) |

- 기록 수가 모자란 종류는 선택이 꺼져 있다. 처음에는 가능한 가장 많은 칸으로 열린다
- **고른 칸이 모두 사진이면 JPEG, 하나라도 영상이면 MP4**
- MP4 길이 = 고른 칸 중 **가장 긴 영상 길이**, 30fps. 사진 칸은 멈춰 있고, 짧은 영상은 마지막 장면에서 멈춘다
- 크기 1080×1080. 칸 사이는 흰 선 6px, 각 칸은 가운데를 잘라 넣는다
- 라벨: 전후·3분할은 칸마다 "N일째", 전체는 편물 이름과 "N일째 · 9월 17일"
- 만드는 중 표시: MP4는 "만드는 중 N%", JPEG는 "만드는 중"
- 종류를 바꾸면 만들던 MP4는 취소된다
- 저장 버튼: 공유 창이 있으면 "사진첩에 저장", 없으면 "파일로 저장"
  - 안내: 열리는 공유 창에서 "비디오 저장"(MP4) 또는 "이미지 저장"(JPEG)을 누른다
  - 공유 창을 취소해도 오류가 나지 않는다
- 파일 이름: `knitting-{편물 앞 8자}-{single|beforeAfter|triple}.{jpg|mp4}`

## 13. 성장 영상

- 기록 2개부터. 적으면 "기록이 2개 이상 있어야 영상을 만들 수 있어요"
- 사진 한 장이 머무는 시간: 기록 8개 이하 0.5초, 24개 이하 0.25초, 그보다 많으면 0.125초
- 영상 기록은 클립을 재생한다
- **마지막 기록은 1초 더 머문다.** 영상이면 마지막 장면에서 멈춘다
- **전체 길이는 60초를 넘지 않는다.** 넘으면 긴 클립부터 같은 길이로 잘라 앞부분만 재생한다 (클립 하나는 최소 1초). 잘린 클립은 남은 시간 동안 그 장면에서 멈춘다
  - 사진이 아주 많으면 60초를 넘을 수 있다
- 1080×1080, 30fps, H.264 MP4
- 시트 문구
  - 만드는 중: "기록 N개 → 약 X초 · N%". **만드는 동안에는 시트를 닫을 수 없다**
  - 완료: "영상이 준비됐어요" + "X초 · N프레임 · N.NMB"
  - 실패: "만들지 못했어요" + 다시 시도 / 닫기
- **화면을 떠나면 만들던 영상은 취소된다**
- 파일 이름: `knitting-{편물 앞 8자}.mp4`
- 영상 만들기를 지원하지 않는 브라우저에서는 **버튼을 누른 뒤에야** "이 브라우저는 영상 만들기를 지원하지 않아요…"가 나온다 **(알려진 한계)**

## 14. QA 우선 확인 목록 (iPhone Safari)

1. 세로로 들고 **동그란 물건** 녹화 → 저장된 영상에서 원이 찌그러지지 않는가
2. 같은 물건을 사진 모드로 촬영 → 비율이 맞는가
3. 5초 자동 정지가 조용히 되는가, 1초 미만이 거부되는가
4. 앨범에서 세로 영상 가져오기 → 회전이 맞고 5초로 잘리는가
5. 녹화 중 앱 전환 → 거기까지 저장되는가
6. 사진+영상 섞어 전후·3분할 → MP4가 사진첩에 저장되는가
7. 성장 영상 → 안내한 길이와 실제 길이가 같고, 클립이 재생되는가
8. 영상 기록을 여러 개 만들고 성장 영상 → 탭이 죽지 않는가
9. 편물 공개 범위를 바꾸면 **과거 기록까지** 바뀌는가
10. 비공개 계정 프로필을 모르는 사람이 열면 "없는 사용자예요"가 나오는가
