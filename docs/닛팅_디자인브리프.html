1주차 화면 디자인

Claude Design에 그대로 붙여넣을 프롬프트와 화면별 사양. 여기서 나온 시안을 Claude Code에 넘겨 실제 화면으로 만든다.

01범위

1주차에 폰에서 동작할 화면은 셋이다. 이번 디자인 세션은 여기까지만 다룬다.

화면완성도이유
편물 목록 (홈)기본형흔한 형태. 토큰만 지키면 됨
촬영제대로여기는 UI가 곧 기능. 아래 설명
타임라인 (편물 상세)기본형사진이 주인공이라 UI는 최소

촬영 화면만 공들이는 이유 — 고스트 레이어 투명도 토글이 어디 있는지, 격자가 어떻게 보이는지, 셔터가 엄지에 닿는 위치인지가 "각도를 맞출 수 있느냐"를 직접 결정한다. 대충 만들면 도그푸딩의 첫 질문에 답을 얻지 못한다.

제외: 앱 아이콘, 스플래시, 다크 모드, 애니메이션, 피드·댓글·프로필 화면. 전부 나중.

02디자인 방향

이 앱의 화면에서 가장 화려한 것은 사용자가 찍은 편물 사진이어야 한다. UI가 눈에 띄면 실패다.

세 가지 원칙

  1. UI는 물러난다. 배경은 거의 무채색, 장식 없음. 사진이 유일한 색이다.
  2. 강조색은 차갑게, 아주 조금만. 뜨개 사진은 대부분 따뜻한 색(실, 나무 바늘, 손)이다. UI 강조색이 차가우면 사진이 튀고, 따뜻하면 사진과 싸운다.
  3. 쌓임을 보여준다. 이 앱의 주제는 시간이 쌓이는 것이다. 진행 상태를 숫자보다 누적된 형태로 보여준다.

피할 것

"수공예 앱" 기본값을 쓰지 않는다. 크림색 배경 + 세리프 제목 + 테라코타 강조는 뜨개·베이킹·도예 앱이 전부 쓰는 조합이고, 아무 브랜드도 만들지 못한다. 손글씨체, 실뭉치 일러스트, 둥근 카드에 그림자, 파스텔 그라데이션도 같은 이유로 제외한다.

03첫 프롬프트

Claude Design에 이것을 그대로 붙여넣는다.

붙여넣기 → Claude Design
뜨개질 기록 앱 "Knitting 닛팅"의 모바일 화면 4개를 디자인해줘. iOS와 Android 공용이고, 세로 화면(390 × 844) 기준이야.

## 앱이 하는 일
사용자가 뜨고 있는 편물을 매일 같은 각도로 촬영해서 쌓아두면, 나중에 그 사진들이 이어져 편물이 자라나는 영상이 된다. 같은 각도로 찍게 만드는 것이 이 앱의 핵심이다.

## 디자인 원칙
1. 화면에서 가장 화려한 것은 사용자가 찍은 편물 사진이어야 한다. UI는 물러난다.
2. 배경은 거의 무채색. 장식 요소 없음. 그림자 없이 1px 경계선으로만 구분한다.
3. 강조색은 차가운 청록 하나만, 아주 적게 쓴다. 뜨개 사진은 대부분 따뜻한 색이라 UI가 차가워야 사진이 산다.
4. 진행 상태는 숫자보다 "쌓인 형태"로 보여준다. 이 앱의 주제가 시간이 쌓이는 것이기 때문이다.

## 절대 하지 말 것
- 크림색 배경 + 세리프 제목 + 테라코타 강조 조합 (수공예 앱의 뻔한 기본값)
- 손글씨체, 실뭉치·바늘 일러스트, 파스텔 그라데이션
- 카드마다 둥근 모서리와 회색 그림자를 다는 SaaS 템플릿 느낌
- 이모지

## 색
배경 #F7F6F3 / 표면 #FFFFFF / 본문 #1A1C18 / 보조 텍스트 #6B6F68 / 경계선 #E2E1DC / 강조 #1F5F5B / 경고 #A3452A

## 타이포·간격
시스템 서체. 크기 28/20/17/15/13. 굵기 400과 600만. 간격은 4px 배수. 모서리는 카드 12, 버튼 10, 사진 8.

## 화면 4개

### 1. 편물 목록 (홈)
- 상단: "내 편물" 제목, 우측에 편물 추가 버튼
- 편물 카드 목록. 카드 하나에: 대표 사진(정사각 썸네일), 편물 이름, 시작한 지 며칠째, 사진 몇 장
- "사진 몇 장"을 숫자로만 쓰지 말고 쌓인 형태로도 보여줘. 작은 눈금이 개수만큼 채워지는 식
- 하단 탭바: 편물 / 촬영(가운데, 강조) / 설정
- 편물이 하나도 없을 때의 빈 화면도 같이. "첫 편물을 만들어 보세요" 같은 안내와 버튼 하나

### 2. 촬영 화면 (가장 중요)
전체 화면 카메라. 아래 요소가 전부 필요해.
- 화면 대부분은 정사각(1:1) 카메라 미리보기. 위아래는 어두운 여백
- 미리보기 위에 직전 사진이 반투명하게 겹쳐 보임 (고스트 레이어)
- 고스트 투명도 토글: 끔 / 30% / 60% 세 단계. 현재 선택된 것이 보여야 함
- 3×3 격자 토글
- 하단 중앙에 큰 셔터 버튼. 엄지로 닿는 위치
- 셔터 좌측에 앨범에서 가져오기, 우측에 취소 또는 닫기
- 상단에 지금 찍는 편물 이름
- 조작 버튼은 사진을 가리지 않게 여백 영역에 배치할 것

첫 촬영일 때(겹칠 직전 사진이 없을 때)의 화면도 따로. 고스트 레이어 대신 "편물을 화면 중앙에, 배경은 단색으로 두세요" 안내가 뜬다.

### 3. 타임라인 (편물 상세)
- 상단: 편물 이름, 시작일, 경과일
- 큰 사진 한 장이 화면을 채움 (정사각)
- 아래에 좌우로 미는 스크러버. 밀면 사진이 시간순으로 바뀜. 어느 시점인지 보여야 함
- 사진 아래 촬영 날짜
- 하단에 "영상 만들기" 버튼 하나 (아직 동작 안 하지만 자리는 잡아둠)

### 4. 편물 만들기 시트
- 아래에서 올라오는 시트
- 입력 두 개: 편물 이름, 시작일
- 하단에 만들기 버튼

각 화면을 나란히 볼 수 있게 배치해줘.

한 번에 다 나오지 않아도 정상이다. 4개를 한 번에 요청한 이유는 서로 일관되게 나오게 하기 위해서다. 마음에 안 드는 화면은 아래 개선 프롬프트로 하나씩 고친다.

04반복 개선 프롬프트

첫 결과를 보고 필요한 것만 골라 쓴다. 한 번에 하나씩 요청하는 편이 결과가 좋다.

흔한 첫 문제

UI가 너무 눈에 띌 때
UI가 사진보다 눈에 띄어. 강조색 사용을 줄이고, 카드 배경과 페이지 배경의 대비를 낮추고, 경계선을 더 얇게 해줘. 사진 썸네일이 화면에서 가장 밝고 선명한 요소가 되어야 해.
수공예 앱 느낌이 날 때
지금 흔한 수공예 앱처럼 보여. 따뜻한 배경색을 더 중립적으로 바꾸고, 둥근 모서리를 줄이고, 장식적인 요소를 전부 빼줘. 사진 관리 도구에 가깝게, 취미 앱보다는 기록 도구처럼 보이게 해줘.

촬영 화면 전용

고스트 레이어를 더 분명하게
촬영 화면에서 고스트 레이어가 어떻게 보이는지 더 분명하게 보여줘. 직전에 찍은 편물 사진이 현재 카메라 화면 위에 반투명하게 겹쳐 있고, 사용자가 그 윤곽에 맞춰 편물을 두는 상황이야. 투명도 30%일 때와 60%일 때를 각각 보여줘.
조작부 위치 조정
촬영 화면의 조작 버튼들이 사진 영역을 가리지 않게 해줘. 정사각 미리보기 영역은 완전히 비워두고, 모든 토글과 버튼은 위아래 어두운 여백에만 배치해줘. 셔터는 한 손 엄지로 닿는 하단 중앙에.
토글 상태가 안 보일 때
고스트 투명도 토글에서 지금 어느 단계가 선택되어 있는지 한눈에 보이지 않아. 선택된 상태를 훨씬 분명하게 만들어줘. 어두운 배경 위라서 명도 차이만으로도 읽혀야 해.

목록·타임라인

쌓임 표현 다시
편물 카드에서 "사진 몇 장"을 쌓인 형태로 보여주는 부분을 다시 해줘. 진행률 바처럼 보이면 안 돼 — 목표가 있는 게 아니라 그냥 쌓이는 거니까. 작은 눈금이 옆으로 늘어나는 형태가 좋겠어.
스크러버 조작감
타임라인 스크러버를 다시 해줘. 사진이 50장 넘어도 쓸 수 있어야 하고, 지금 몇 번째를 보고 있는지와 전체가 몇 장인지가 같이 보여야 해. 처음과 마지막으로 바로 가는 방법도 있으면 좋겠어.

마무리

일관성 점검
네 화면의 간격, 글자 크기, 버튼 모양이 서로 일치하는지 점검하고 어긋난 곳을 맞춰줘. 그리고 쓰인 색·크기·간격 값을 목록으로 정리해줘. 코드로 옮길 때 쓸 거야.
작은 화면 확인
화면이 작은 기기(360 × 640)에서 어떻게 보이는지도 보여줘. 특히 촬영 화면에서 정사각 미리보기와 조작부가 다 들어가는지 확인이 필요해.

05리뷰 체크리스트

시안이 나오면 이걸로 본다. Claude Design에서 나온 결과를 Claude Code로 넘기기 전 관문이다.

공통

  • 사진이 화면에서 가장 눈에 띄는 요소인가
  • 색·글자 크기·간격이 정해둔 값만 쓰였는가 (임의값이 섞이지 않았는가)
  • 그림자 없이 경계선만으로 구분되는가
  • 본문 글자와 배경의 대비가 충분한가 (보조 텍스트가 회색으로 흐려지지 않았는가)
  • 누를 수 있는 요소가 최소 44 × 44 이상인가
  • 빈 상태 화면이 안내와 다음 행동을 주는가

촬영 화면 — 여기는 더 깐깐하게

  • 정사각 미리보기 영역에 조작 요소가 하나도 겹치지 않는가
  • 고스트 투명도 세 단계 중 현재 값이 한눈에 보이는가
  • 셔터가 한 손 엄지로 닿는 위치인가
  • 첫 촬영(고스트 없음) 화면이 따로 있는가
  • 어두운 실내에서도 조작부가 보이는가 (밝기 대비)
  • 한 손으로 뜨개바늘을 든 채 조작할 수 있는 배치인가

마지막 항목이 실전 기준이다. 뜨개하다 말고 사진을 찍는 상황이라 손이 자유롭지 않다. 양손이 필요한 배치면 도그푸딩에서 바로 "귀찮다"가 나온다.

Android 확인 — 놓치기 쉬움

  • 상단 상태바·하단 제스처 바 영역에 중요한 요소가 걸치지 않는가
  • 하단 탭바가 제스처 바와 겹치지 않는가

Android 16을 타깃하면 화면 가장자리까지 콘텐츠가 그려지는 모드가 강제된다. 시안 단계에서 안전 영역을 표시해두면 코드에서 실수하지 않는다.

06Claude Code로 넘기기

시안이 확정되면 디자인 토큰부터 코드로 만든다. 화면보다 먼저다.

붙여넣기 → Claude Code
디자인 시안이 확정됐어. 화면 코드를 쓰기 전에 디자인 토큰 파일부터 만들어줘.

src/shared/ui/tokens.ts 에 색·글자 크기·굵기·간격·모서리 반경을 상수로 정의하고, 앞으로 모든 화면은 이 상수만 참조하도록 해. 스타일에 색상값이나 픽셀 숫자를 직접 쓰지 않는다.

값은 아래와 같아:
[Claude Design이 정리해준 값 목록을 여기 붙여넣기]

그리고 자주 쓸 공통 컴포넌트를 src/shared/ui/ 아래에 만들어줘. 지금 필요한 건 이 정도야:
- 기본 버튼 (주요/보조 두 가지)
- 편물 카드
- 빈 상태 안내
- 하단 시트

각 컴포넌트는 토큰만 참조하고, 화면별 예외 스타일을 받지 않게 해줘.

토큰과 컴포넌트가 먼저 있으면 이후 화면들이 자동으로 일관돼진다. 반대로 화면을 먼저 만들면 색과 간격이 화면마다 흩어져서, 나중에 하나 바꿀 때 전부 열어야 한다.

넘길 때 같이 전달할 것 — 시안 이미지, Claude Design이 정리해준 값 목록, 그리고 이 문서의 05장 체크리스트. 마지막 것은 Claude Code가 만든 화면을 검수할 때 다시 쓴다.
