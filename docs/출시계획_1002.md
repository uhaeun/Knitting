둘 다 [테스트케이스](테스트케이스.md)의 같은 항목을 쓴다. 기기만 다르다.
**Android는 한 번도 안 봤으므로 9/20~21에 1차를 돌린다.** 마지막 주에 몰면 고칠 시간이 없다.

Android에서만 따로 볼 것

- 홈 화면 추가(Chrome "설치" 안내)가 뜨는가
- 촬영·녹화가 되는가 (코덱이 iPhone과 다르다)
- 공유 창으로 사진·영상이 갤러리에 저장되는가
- 뒤로 가기 버튼으로 화면이 깨지지 않는가

**아직 안 정한 것**: 다희 님이 기능 개발(5번 비밀번호 찾기, 7번 프로필 편집)까지 맡을지. 맡으면 로컬 Supabase 세팅 반나절이 먼저다. QA만 하면 세팅 없이 오늘 시작할 수 있다.

## 10/2 이후: 하이브리드 앱 (2026-09-18 결정)

웹 배포는 계속 유지하고, 그 위에 **웹뷰로 감싼 앱**을 만들어 스토어에 올린다. 카메라와 저장은 네이티브 기능을 쓴다.

**왜** 카메라 권한을 매번 묻는 것과, 사진첩에 바로 저장이 안 되는 것(공유 창을 한 번 더 눌러야 함)이 웹앱의 가장 큰 불편이다. 알림도 홈 화면 추가 없이 받을 수 있다.

**무엇을 네이티브로** 카메라 촬영·녹화 · 사진첩 저장 · 알림. 나머지 화면과 영상 합성은 웹 그대로 쓴다.

**위험** 애플이 "웹사이트를 그대로 감쌌다"고 반려할 수 있다(가이드라인 4.2). 네이티브 카메라·저장·알림이 들어가면 통과 가능성이 올라간다. 또 웹뷰(WKWebView)에서 지금의 영상 처리(WebCodecs·Mediabunny)가 되는지 **하루짜리 시험**으로 먼저 확인한다.

**일정** 10/2 웹 공개 → 10월 중순 시험 1일 → 착수 2~3주 → 11월 초 심사 제출.

**도구** 이 맥에 Xcode 26.6 · CocoaPods 1.16.2 · Android SDK · Java가 이미 있다. 개발자 계정만 있으면 된다 (애플 연 99달러, 구글 25달러 1회).
