운영자 수동 재처리·권한·감사

운영 미적용 · 전체 출시 승인은 별도

운영 DB·Storage·실사용자 데이터와 운영자 계정·역할을 변경하지 않았습니다. 가상 계정과 파일만 사용하는 분리 환경에서 검증했습니다. 기존 0001~0025와 요구사항 정책은 유지하고 신규 0026을 추가했습니다.

조회 버튼은 삭제나 재처리를 실행하지 않습니다. 일부 성공은 전체 완료가 아닙니다.

변경과 영향

항목최종 동작
조회·실행 권한조회 전용 viewer와 실행자 executor를 분리했습니다. 기본 운영자는 없으며 일반 사용자·익명 사용자는 내부 표·관리 RPC에 접근할 수 없습니다. 역할 회수·재부여는 세대를 바꿔 과거 확인창과 대기 요청을 되살리지 않습니다. 보존 검토 권한은 별도입니다.
단건 확인창결과물 ID, 미삭제 파일 수·종류, 자동 6회 소진, 삭제 여부, 링크 차단, 보존 판단, 마지막 오류와 시각을 새로 조회합니다. 취소·닫기는 재처리 요청을 보내지 않습니다. 조회 실패는 0건/안전으로 표시하지 않습니다. 확인은 5분 내에 유효하며 상태가 바뀌면 거절합니다.
정확한 범위·중복 방지서버 manifest의 원본·대표 이미지 중 미완료 파일만 처리합니다. 다건·폴더·와일드카드·임의 경로 입력은 받지 않습니다. 단건 잠금, 임대, 멱등 요청 ID로 중복 실행을 막고 실행자당 분당 최대 5개 수동 작업을 허용합니다. 성공 파일은 다음 요청에서 제외합니다.
정책과 삭제 안전자동 최초+추가 5회 카운터·예약을 초기화하지 않습니다. 수동 횟수와 감사 이력만 따로 남깁니다. 미확인 CDN·보존 hold·검토 변경·탈퇴 절차·권한 회수·잘못된 경로는 우회하지 않습니다. 실제 Storage 삭제 트랜잭션에서도 조건을 다시 검사합니다. 물리 삭제가 완료되면 되돌릴 수 없습니다.
결과와 감사이번 작업의 성공·부분 성공·실패·보류와 누적 전체 완료를 구분합니다. 요청자·시각·객체별 결과·거절·부재 검증·오류 식별자·버전을 보존합니다. 실행 전 거절도 결과물별 감사 화면에서 확인할 수 있습니다. 제목·미디어·Storage 경로·서명 URL·토큰은 관리 DTO에 복제하지 않습니다.
조회 중단·복구활성 화면에서 대기/처리 중인 작업만 완료 시점 기준 10초마다 단일 조회합니다. 8초 시간초과, 연속 3회 실패, 권한 401/403, 무결성 오류를 구분합니다. 오류 중단은 복귀·네트워크 연결로 풀지 않고 명시적인 정상 수동 확인으로만 복구합니다. 권한 상실 시 목록·상태·감사 캐시를 즉시 숨깁니다.
복귀·최신성·버전복귀 즉시 조회는 5초 간격이며 중복 이벤트와 밀린 10초 조회를 하나로 합칩니다. BIGINT 버전은 문자열로 반환하고 한 트랜잭션의 상태 변경마다 1회만 증가합니다. GET은 버전을 늘리지 않습니다. 동일 버전의 상태 충돌·역행 시 최대 1회만 후속 조회하고 반복되면 멈춥니다. 버전 상한 전에 외부 삭제를 차단하고 새 작업으로 상한을 초기화하지 않습니다.

분리 환경 검증과 증거

실제 일회용 Supabase에서 운영자 통합 8개 시나리오를 모두 통과했습니다. 실제 Storage 장애로 각 파일의 자동 6회를 소진시킨 뒤 확인창 취소·오래된 확인 거절·조회 전용 권한·멱등 요청·버전 1→3→5·부분 성공을 확인했습니다. 실제 403에서 목록/상태/감사를 숨기고 재승인 후 명시적인 수동 조회로 복구했습니다. claim 뒤 권한 회수 시 Storage가 삭제를 거절했고, 새 확인 후 남은 썸네일만 삭제해 내부 물리 파일까지 없어졌습니다. 최소 오류 감사 중복 방지와 버전 한도도 통과했습니다. 기존 P0 인증·구URL 회수·결과물 정리·앱 종료 후 서버 예약 및 웹 회귀 30개도 모두 통과했습니다. 타입·린트·단위 237개·웹 export도 통과했습니다.

  • 최종 제품 코드 0642945: 최종 분리 Supabase 검사 · 타입·린트·단위 검사
  • 기존 화면 30개를 포함하는 전체 회귀. 최종 제품 코드 0642945에서 전체 회귀와 새 운영자 통합 검사를 함께 실행해 통과했습니다.
  • SQL 254건: 권한 53 + 기존 P0 76 + 링크 35 + 정리 46 + 운영자 44. 로컬 PostgreSQL 14의 가상 Auth/Storage 인터페이스입니다. 실제 Supabase HTTP·물리 파일 검증과 구분합니다.
  • 실제 중첩 트랜잭션 5건: 동일 요청 멱등성, 중복 claim, 권한 회수 선행 삭제 차단, 삭제 선행 시 회수 직렬화, 중복 완료 거절. 추가 1건은 만료된 수동 임대 복구이며 자동 카운터·예약을 되살리지 않았습니다.
  • 단위 검사 237건 중 새 조회/스냅샷·캐시 검사는 38건입니다. 가상 시간으로 0→8초 실패→18초 재조회, 3회 중단, 수동 복구, 활성/비활성, 정확히 5초 경계, 만료 예약 단건 복원, 중복 클릭, 오래된 응답, BIGINT 정밀도·버전 한도·대상 교체·횟수 역행을 검사합니다.

최초 통합 실행은 부분 성공 문구에 버전이 붙은 것을 검사에서 누락해 실패했습니다. 실제 원본 삭제·대표 이미지 보존과 서버 버전 1→3→5는 통과했으며 화면에서도 부분 성공이 확인됐습니다. 문구 검사를 수정하고 권한 회수 화면 검사를 추가했습니다. 권한을 회수했다가 다시 부여했을 때 조회 캐시 연결이 끊겨 수동 확인 결과가 표시되지 않는 결함도 발견해 수정했습니다. 캐시 내용만 비우고 조회 연결은 유지하며, 권한 오류 중단은 명시적인 최신 수동 확인으로만 복구합니다. 해당 캐시 회귀 검사 2개와 화면 생명주기 복구를 보강했습니다. 감사 오류 기록의 중복 방지 SQL에서 발견한 인자/열 이름 충돌도 고치고 DB 회귀 검사에 추가했습니다. 실패 기록은 성공 증거로 합산하지 않습니다.

상태 API 계약

operator_cleanup_status는 저장된 작업 상태 한 행의 일관된 스냅샷과 작업 ID, 문자열 버전, UTC checked_at, 요청 nonce를 반환하는 읽기 전용 GET입니다. 높은 버전이 우선이며 같은 버전에서는 서버 시각과 동일한 객체 상태를 확인합니다. 작업 내 파일 식별자·자동 횟수·이미 완료된 파일은 바뀔 수 없습니다.

클라이언트 시계로 서버 시각을 추정하지 않습니다. 수동 클릭 이후 전송한 GET의 nonce를 서버가 응답에 돌려주는 인과관계를 최신 관측 기준으로 사용합니다. 클릭 전에 시작한 자동 요청은 이 증명이 없으므로 완료 후 최대 한 번만 새 GET을 보냅니다. 반복 클릭은 하나로 합치며 무결성 보정 조회도 한 번으로 제한합니다. 오류 보고는 최소 필드만 별도 POST로 기록하고 작업 재실행은 하지 않습니다.

테스트 환경 적용 순서

  1. 기존 마이그레이션 뒤 신규 0026_operator_cleanup.sql과 새 앱 코드를 적용합니다. DB 변경은 Supabase CLI의 파일 단위 트랜잭션으로 적용하며, psql로 직접 적용한다면 --single-transaction을 사용합니다. 공식 CLI 실행 방식을 기준으로 적용 중 권한/함수의 일부만 노출되는 상태를 피합니다. 기존 cleanup-results 워커·서버 비밀키·예약을 그대로 사용합니다. 이번 작업에서 운영 적용은 수행하지 않았습니다.
  2. 실제 승인된 계정에만 별도 환경에서 cleanup_operators의 viewer/executor 역할을 관리자가 부여합니다. 실제 사용자를 기본 등록하거나 보존 검토자를 함께 만들지 않습니다. 권한 회수는 deleted_at 또는 역할 변경으로 처리합니다.
  3. 기존 링크 차단과 권한 있는 보존 검토가 확인된 가상 삭제 결과물에서 자동 시도 소진·단건 확인·부분 성공·권한 회수·감사 이력을 다시 확인합니다. 일반 사용자 화면 → 내 결과물 → 삭제 결과물 정리 상태의 운영자 진입은 권한이 있을 때만 나타납니다. 관리 경로는 /operations입니다.
  4. Storage 버전·예약·실제 환경 설정을 확인하고 검증 증거를 확보한 뒤 운영 적용을 별도로 판단합니다. PR은 초안이며 main 병합·배포·실제 역할 부여를 하지 않았습니다.

남은 출시 조건

  • 실제 hosted CDN: 전용 프로젝트가 없어 미검증입니다. 운영 CDN으로 대체하지 않았으며 legacy 게이트는 계속 닫혀 있습니다. 이번 수동 기능도 우회하지 않습니다.
  • 운영 준비: 실제 운영자 승인·최소 권한 부여, 보존 판단과 검토 근거, 백업·로그 보존과 예외 접근 권한, 실제 함수·예약 구성은 적용하거나 완료로 판정하지 않았습니다.
  • 실기기: 이번 UI 자동 검사는 Chromium 웹입니다. iOS/Android 실기기의 앱 전환·복귀·권한 상실 검증은 별도입니다. 타이머 경계는 단위 가상 시간 검사입니다.
