- 하은은 촬영·결과물과 iPhone, 다희는 계정·소셜과 Android를 주로 맡되 핵심 가입→촬영→저장은 두 사람이 각각 끝까지 수행한다.

## 자동 검사를 보강할 순서

1. 타입·단위 검사 CI의 Node 20을 다른 워크플로와 같은 Node 22 계열로 맞춘다. [Expo 57 공식 문서](https://docs.expo.dev/versions/v57.0.0/)는 최소 Node 22.13.x를 명시한다.
2. lint 오류를 정리하고 PR 검사에 lint를 추가한다. 현재 PR 초록불은 타입·단위 검사만 의미한다.
3. PR에서 핵심 E2E(가입, 촬영·저장, 결과물)를 돌린다. 전체 29개는 main 및 출시 후보에서 확인한다. 중요한 인증·DB·미디어 변경에는 관련 E2E를 추가한다.
4. 로컬 Supabase를 띄우는 CI에 RLS SQL을 연결한다. 현재 SQL은 실패 건수를 출력할 뿐 assertion 예외를 던지지 않으므로, 단순 `psql` 성공 코드만 보지 않고 실패건수 0을 강제한다.
5. E2E 실행기는 `RESULT: PASS` 문자열뿐 아니라 프로세스 종료 코드·timeout도 확인하도록 한다. 필수 검사 SKIP을 출시 통과로 처리하지 않는다. 지금은 영상 검사 키가 없으면 SKIP 후 전체가 성공 종료될 수 있다.
6. 권한 검사는 현재 DB 전체를 포괄하지 않는다. 마이그레이션 0006~0012의 계정 삭제·복원·알림·댓글·순서·오류 수집 권한을 변경할 때 성공/거부 회귀 검사를 보강한다.

Appium 개수를 늘리는 일보다 실제 플랫폼 차이를 검증하는 데 집중한다. 가입 화면·댓글 같은 공통 웹 흐름은 Playwright로, OS 권한·갤러리 저장·알림·앱 복귀는 Appium 및 실기기로 다룬다.

## 실기기 QA 최소 묶음

웹을 공개한다면 iPhone Safari와 Android Chrome에서, 앱을 배포한다면 해당 설치본에서도 수행한다. 앱 통과를 브라우저 통과로 대신하지 않는다.

| 흐름 | 정상 동작 | 실패·경계 조건 |
|---|---|---|
| 가입·복귀 | 메일 인증 → 첫 설정 → 재로그인 | 만료 링크, 재전송, 비밀번호 재설정, 앱/브라우저 복귀 |
| 사진 기록 | 촬영 → 목록 → 상세 → 재실행 후 유지 | 권한 거부 후 허용, 빠른 연타, 업로드 중 연결 끊김·재시도 |
| 영상 기록 | 촬영·앨범 → 재생 → 성장 영상 | 세로/가로·회전, 짧은/긴 클립, 앱 전환 후 복귀 |
| 결과물 | 결과 사진 3종·성장 영상 생성 → 사진첩에서 열기 | 공유 취소, 저장 권한 거부, 잘림·비율·화질·길이 |
| 데이터·권한 | 공개/비공개, 팔로우, 차단, 휴지통·복원 | 계정 B로 접근 차단 확인, 삭제된 링크 재접근 |
| 계정 삭제 | 삭제 후 재로그인 및 데이터 노출 확인 | 실패 안내, 남은 세션·다른 계정에서의 조회 |
| 앱 고유 기능 | 권한 유지, 사진첩 저장, 촬영 알림 | 앱 종료·재실행, 백그라운드, 알림 해제 |

사진만/영상만/혼합 편물과 계정 A/B를 준비한다. 자동화는 로컬·테스트 서버에서 수행하고 운영 데이터 정리는 소유자·삭제 범위를 확인한 별도 작업으로 한다.
