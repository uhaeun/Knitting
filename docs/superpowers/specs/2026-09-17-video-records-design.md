# 영상 기록 설계 (2026-09-17)

매일 기록에 사진뿐 아니라 **최대 5초 영상**도 올린다. 타임라인은 사진·영상이 섞이고, 결과물(전체·전후·3분할, 성장 영상)은 기록 종류와 상관없이 만든다.

웹앱(iPhone Safari 주 사용) 기준. 네이티브 코드는 쓰지 않는다.

## 0. 선행 시험 — 통과해야 본 구현에 들어간다

iPhone Safari에서 버리는 시험 페이지로 확인한다 (앱 코드·실데이터와 분리된 별도 주소).

| 확인 | 통과 기준 |
|---|---|
| 5초 녹화 (MediaRecorder) | 녹화 파일이 만들어진다 |
| 정사각 1080 · H.264 · 무음 · 5초 변환 (Mediabunny) | **10초 이내**, 3회 연속 페이지가 튕기지 않는다 |
| 변환 결과를 프레임으로 읽기 (합성·성장 영상에 필요) | 150프레임 전부 읽힌다 |
| 앨범 영상 가져오기 | 회전이 바르게 반영된다 (눈으로 확인) |

**통과 못 하면** 설계를 바꾼다: 720 해상도, 또는 변환 없이 원본 저장 + 재생 시 CSS로 정사각 표시.

### 시험 결과 (2026-09-17, iPhone · iOS 18.7 · Safari 26.6.1) — 통과

| 확인 | 결과 |
|---|---|
| 5초 녹화 → 정사각 1080 변환 | 5.0초 (반복 5.1 / 5.3 / 5.7초, 튕김 없음) |
| 프레임 읽기 | 149장 0.3~0.6초 |
| 결과 | 1080×1080 H.264, 무음, 약 2.4MB |
| 앨범 영상 9.5초 (가로) | 5초로 잘라 5.6초 |
| 코덱 지원 | H.264·HEVC 읽기 가능, H.264 1080 인코딩 가능 |

시험에서 알게 된 것 → 구현에 반영

- **녹화 형식은 코덱까지 명시한다** (`video/mp4;codecs=avc1…`). `video/mp4`만 주면 브라우저가 안에 넣는 코덱이 다르다 (Chromium은 VP9를 넣고 스스로 못 읽음)
- iPhone 녹화본에 **회전 90° 정보**가 붙는다. 크롭은 회전 적용 후 크기(`displayWidth/Height`) 기준
- **미해결: 세로로 들고 녹화→변환한 결과가 홀쭉해짐** (카메라 화면은 정상). 제작 환경의 세로 회전 영상 변환은 정상이라 iPhone 녹화본 특유 문제로 본다. 유력 원인은 정사각 크기(2560×2560) 요청 시 녹화 파일이 눌려 기록되는 것
  - 대응: 영상 모드에서는 카메라에 정사각 크기를 요청하지 않는다 (가로 1920만 요청), 크롭은 정사각 픽셀 기준(`squarePixelWidth/Height`, 픽셀비율 반영)
  - 검증: E2E에 원이 원으로 남는지 검사, 2단계 끝에 iPhone에서 동그란 물건으로 확인
  - 같은 요청을 쓰는 **사진 촬영도 iPhone에서 비율 확인 필요**
- 반복 변환 시 조금씩 느려짐 (5.0→5.7초) → 변환마다 Input·디코더를 닫는다

## 1. 데이터와 저장소 (`0005`)

- `posts`에 컬럼 추가
  - `media_type`: `'photo'`(기본) | `'video'`
  - `video_path`: 영상 Storage 키. 사진이면 null
  - `duration_ms`: 영상 길이. 사진이면 null
  - 제약: `media_type = 'video'` ⇔ `video_path`·`duration_ms`가 있음, `duration_ms` ≤ 5500 (인코딩 여유)
- 영상 기록도 `photo_path`(1440 JPEG)·`thumb_path`(400)에 **첫 장면**을 대표 사진으로 저장한다 → 목록 표지·피드 격자·고스트 레이어는 변경 없이 동작
- 영상 형식 고정: 1080×1080, H.264 MP4, 무음, 30fps, 약 4Mbps (5초 ≈ 2.5MB)
- Storage: `photos` 버킷에 `{owner}/{project}/{post}.mp4`. 허용 MIME에 `video/mp4` 추가, 용량 제한 5MB → 10MB
- `photos_select` 정책의 "그 파일을 쓰는 게시물이 보일 때"에 `video_path` 추가 (없으면 남의 공개 영상이 안 열린다)
- `rls_matrix.sql`: 제약 위반 거부(영상인데 경로 없음, 5.5초 초과), 타인의 공개 영상 파일 읽기 허용·비공개 거부

## 2. 촬영과 저장

- 촬영 화면에 **[사진 | 영상]** 전환 (마지막 선택 기억)
- 영상 모드: 셔터 한 번 = 녹화 시작, 다시 = 끝. 5초 자동 정지. 1초 미만은 저장하지 않고 안내
- 녹화 중에도 겹치기·격자 표시. 셔터 빨간 테두리 + `0:03 / 0:05`
- 앨범에서 가져오기: 영상 모드에서는 영상 선택. 5초 초과는 앞 5초만 쓰고 알린다
- 저장 파이프라인 (순서 고정)

```
녹화 → 정사각 크롭·1080·H.264·무음·5초 자르기 (Mediabunny Conversion)
     → 첫 장면 → 1440 대표 사진 + 400 썸네일
     → 업로드: 영상 → 대표 사진 → 썸네일 → posts INSERT
```

- 실패 시 올린 파일 삭제. **녹화 원본 Blob은 저장 성공까지 메모리에 유지** → 다시 시도는 재촬영 없이 처리만 반복
- 진행 표시: "변환 중 N%" → "올리는 중"

## 3. 보여 주기

- 타임라인: 현재 기록이 영상이면 `<video muted loop playsInline autoplay>` + 대표 사진 포스터 + `▶ 0:04` 배지. 보고 있는 한 개만 로드
- 피드·프로필 격자: 대표 사진 + `▶` 표시, 자동 재생 없음. 게시물 상세에서 자동 반복 재생
- 공통 컴포넌트 `shared/ui/VideoPlayer.tsx`
- `Post`에 `media_type`, `video_path`(서명 URL), `duration_ms`. 발급은 `signPaths` 배치

## 4. 결과물

**결과 사진 화면**
- 칸 고르기 규칙은 그대로 (3분할 가운데 = 시간 기준 한가운데)
- 고른 기록이 모두 사진 → JPEG (현행)
- 하나라도 영상 → **MP4**
  - 길이 = 칸 중 가장 긴 영상 (≤ 5초), 30fps
  - 사진 칸 정지, 영상 칸 재생, 짧은 영상은 마지막 장면에서 정지
  - 라벨·편물 이름은 매 프레임
  - 미리보기는 영상 반복, 안내 문구 "비디오 저장"
- 순수 함수: 출력 종류 판단(`outputKindOf`, `ResultKind`는 이미 전체·전후·3분할 뜻이라 이름을 바꿈), 칸별 시각 → 프레임 매핑

**성장 영상**
- 출력 8fps → **30fps**
- 사진: 머무는 시간은 현행과 같음 (장수에 따라 0.5 / 0.25 / 0.125초)
- 영상: 클립 끝까지 재생 (≤ 5초)
- 마지막 기록 +1초 (영상이면 마지막 장면 정지)
- **전체 60초 상한** (2026-09-17 최종 리뷰 후 추가, 영상이 많으면 결과 파일이 메모리에 통째로 올라가 iPhone 탭이 죽을 수 있음): 넘으면 긴 클립을 같은 길이로 앞부분만 재생 (클립당 최소 1초). 사진이 아주 많으면 60초를 넘을 수 있다
- `plan.ts`를 시간 구간 목록(`{ kind, uri, durationMs }[]`)으로 바꾸고 단위 테스트
- 클립은 한 번에 하나씩 디코드 (메모리)
- `mp4-muxer` 제거, Mediabunny로 교체

## 5. 오류 처리

| 상황 | 동작 |
|---|---|
| 녹화·인코딩 미지원 브라우저 | [영상] 비활성 + 안내. 사진은 그대로 |
| 녹화 중 전화·앱 전환 | 1초 이상이면 거기까지 저장 진행 |
| 변환 실패 | 오류 + 다시 시도 (원본 유지) |
| 업로드·INSERT 실패 | 올린 파일 정리 + 다시 시도 |
| 재생 실패 | 대표 사진 + "영상을 불러오지 못했어요" |
| 결과물·성장 영상 실패 | 오류 + 다시 시도 |

## 6. 테스트

- 단위: 성장 영상 구간 계산, 결과 출력 종류 판단, 녹화 타이머(5초 자동 정지·1초 미만 거부)
- SQL: 1절의 RLS·제약 케이스
- E2E (Chromium 가짜 카메라 + 로컬 Supabase)
  - 3초 녹화 → ffprobe: 1080×1080, h264, ≤5초, 오디오 트랙 없음 / 대표 사진·썸네일 존재
  - 8초 영상 앨범 가져오기 → 5초
  - 사진+영상 전후 → MP4 1080×1080
  - 영상 섞인 성장 영상 → 길이가 구간 계산과 일치
  - 공유 창으로 MP4 전달
- iPhone 수동: 녹화, 변환 시간, 앨범 회전, 섞인 결과물 저장, 성장 영상 시간

## 7. 구현 순서

0. 선행 시험 (위 0절) — 결과에 따라 설계 수정
1. `0005` + 순수 함수 (화면 변화 없음)
2. 촬영·저장 → iPhone 확인
3. 타임라인·피드 재생
