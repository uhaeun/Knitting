카운터 유지 트리거

like_count를 매번 count(*)로 계산하면 인기순 정렬이 느려진다. 트리거로 유지한다.

like_count 트리거
create or replace function bump_like_count()
returns trigger language plpgsql security definer set search_path = public as $$
begin
  if TG_OP = 'INSERT' then
    update posts set like_count = like_count + 1 where id = NEW.post_id;
  elsif TG_OP = 'DELETE' then
    update posts set like_count = greatest(like_count - 1, 0) where id = OLD.post_id;
  end if;
  return null;
end $$;

create trigger reactions_count
after insert or delete on reactions
for each row execute function bump_like_count();

comment_count도 동일 패턴으로 작성한다. 단, 댓글은 soft delete이므로 deleted_at이 채워질 때도 감소시켜야 한다. UPDATE 트리거를 추가할 것.

신고 누적 자동 숨김

24시간 내 사람 대응이 불가능한 구간을 메우는 안전장치다.

신고 3회 자동 숨김
create or replace function auto_hide_on_reports()
returns trigger language plpgsql security definer set search_path = public as $$
declare n int;
begin
  select count(*) into n from reports
   where target_type = NEW.target_type and target_id = NEW.target_id
     and status = 'open';
  if n >= 3 then
    if NEW.target_type = 'post' then
      update posts set hidden_at = now()
       where id = NEW.target_id and hidden_at is null;
    elsif NEW.target_type = 'comment' then
      update comments set hidden_at = now()
       where id = NEW.target_id and hidden_at is null;
    end if;
  end if;
  return null;
end $$;

create trigger reports_auto_hide
after insert on reports
for each row execute function auto_hide_on_reports();

04RLS 설계

원칙

  1. 모든 테이블에 enable row level security. 정책 없는 테이블을 만들지 않는다.
  2. 판정 로직은 stable + security definer 함수로 분리한다. 정책 본문에 인라인 서브쿼리를 두면 행마다 재평가된다.
  3. auth.uid()는 반드시 (select auth.uid())로 감싼다. Postgres가 InitPlan으로 끌어올려 질의당 1회만 평가한다.
  4. 차단은 양방향이다. 차단한 쪽도 차단당한 쪽도 서로 안 보인다.

판정 함수

가시성 판정 헬퍼
alter table profiles  enable row level security;
alter table projects  enable row level security;
alter table posts     enable row level security;
alter table follows   enable row level security;
alter table blocks    enable row level security;
alter table comments  enable row level security;
alter table reactions enable row level security;
alter table reports   enable row level security;

-- 양방향 차단 판정
create or replace function is_blocked_pair(a uuid, b uuid)
returns boolean language sql stable security definer set search_path = public as $$
  select exists (
    select 1 from blocks
     where (blocker_id = a and blocked_id = b)
        or (blocker_id = b and blocked_id = a)
  );
$$;

-- 승인된 팔로워 판정
create or replace function is_accepted_follower(viewer uuid, target uuid)
returns boolean language sql stable security definer set search_path = public as $$
  select exists (
    select 1 from follows
     where follower_id = viewer and followee_id = target
       and status = 'accepted'
  );
$$;

핵심 정책

posts · comments · profiles 정책
-- 게시물 조회
create policy posts_select on posts for select using (
      deleted_at is null
  and hidden_at  is null
  and not is_blocked_pair(owner_id, (select auth.uid()))
  and (
        owner_id = (select auth.uid())
     or visibility = 'public'
     or (visibility = 'followers'
         and is_accepted_follower((select auth.uid()), owner_id))
  )
);

-- 게시물 생성: 본인 소유 프로젝트에만
create policy posts_insert on posts for insert with check (
      owner_id = (select auth.uid())
  and exists (select 1 from projects p
               where p.id = project_id
                 and p.owner_id = (select auth.uid())
                 and p.deleted_at is null)
);

create policy posts_update on posts for update
  using      (owner_id = (select auth.uid()))
  with check (owner_id = (select auth.uid()));

-- 댓글 조회: 부모 게시물이 보이면 보인다
create policy comments_select on comments for select using (
      deleted_at is null
  and hidden_at  is null
  and not is_blocked_pair(author_id, (select auth.uid()))
  and exists (select 1 from posts p where p.id = post_id)
);

-- 댓글 삭제: 작성자 또는 게시물 소유자
create policy comments_delete on comments for delete using (
      author_id = (select auth.uid())
   or exists (select 1 from posts p
               where p.id = post_id and p.owner_id = (select auth.uid()))
);

-- 프로필 조회: 비공개 계정은 본인 · 승인 팔로워만
create policy profiles_select on profiles for select using (
      deleted_at is null
  and not is_blocked_pair(id, (select auth.uid()))
  and (
        id = (select auth.uid())
     or is_private = false
     or is_accepted_follower((select auth.uid()), id)
  )
);

comments_select의 exists (select 1 from posts …)는 posts 정책이 다시 적용되므로 게시물 가시성이 자동으로 상속된다. 조건을 중복 작성하지 않는다.

정책은 눈으로 검증할 수 없다. 아래 조합을 테스트로 고정한다.

rollback;

06미디어 파이프라인

촬영 → 저장

expo-camera 촬영 → EXIF 회전 정규화 (expo-image-manipulator) → 중앙 정사각 크롭 ← 기기별 센서비 차이 흡수 → 1440px 리사이즈 / q80 → 400px 썸네일 생성 → Storage 업로드 (원본 → 썸네일 순) → posts INSERT → 로컬 임시파일 삭제

실패 처리 — 업로드 성공 후 INSERT 실패 시 고아 파일이 남는다. 앱 시작 시 photos/{uid}/ 목록과 posts 테이블을 대조해 정리한다. 반대로 INSERT 후 업로드 실패는 없어야 하므로 순서를 위와 같이 고정한다.

오프라인 — 촬영은 오프라인에서 가능해야 한다. 로컬 큐에 쌓고 온라인 복귀 시 업로드한다. v1 포함 여부는 미정이나, 최소한 업로드 실패 시 재시도 버튼은 필수다.

07인증 흐름

앱 시작 → 세션 확인 (supabase.auth.getSession) → 없으면 로그인 화면 ├ Apple (iOS 네이티브 / Android 웹 리디렉션) └ Google (네이티브 SDK → idToken) → supabase.auth.signInWithIdToken → profiles 행 존재 확인 ├ 없음 → 온보딩(username, display_name) → INSERT └ 있음 → 진입 → eula_version < 현재 버전이면 EULA 전체화면 게이트

계정 삭제 — auth.users 삭제 후 on delete cascade로 전체 정리. Storage는 별도로 지워야 하므로 Edge Function에서 photos/{uid}/ 프리픽스를 일괄 삭제한다.

한국 개발자 필수 항목 — 2026년 1월부터 Sign in with Apple Services ID를 신규 등록하거나 갱신할 때 server-to-server 알림 엔드포인트가 필수다. Supabase Edge Function으로 엔드포인트를 하나 만들어 등록한다. App Store 제출 전 반드시 처리할 것.

10개발 · 배포 루프

코드는 Claude 세션 하나가 작성하고, 하은과 다희는 각자 기기에 설치해 실제로 뜨개하며 쓴다. 발견한 문제를 이슈로 올리면 다시 고친다. 이 반복이 이 프로젝트의 개발 방식이다.

Claude가 기능 구현 → EAS Update로 무선 배포 (1~2분) → 하은 iPhone / 다희 Android 각자 최신 버전 → 실제 편물을 기록하며 사용 → 불편함 · 버그 → GitHub Issue → 다시 위로

배포 주기 — 주 2회. 매일이면 피드백이 쌓일 틈이 없고, 주 1회면 반복이 너무 느리다.

EAS Update — 이 루프의 전제 조건

코드를 고칠 때마다 전체 빌드를 다시 돌리면 20분씩 걸려 반복이 성립하지 않는다. TypeScript 변경은 무선 업데이트로 내린다.

변경 종류배포 방식소요
화면 · 로직 · 스타일 (대부분)eas update → 앱 재시작1~2분
네이티브 모듈 · 패키지 추가 (드묾)eas build 후 재설치15~20분

초기 셋업에 반드시 포함시킨다. 나중에 붙이면 그때까지의 반복 속도를 통째로 잃는다.
