00전체 그림

이 프로젝트의 방식은 코드는 Claude Code가 쓰고, 두 사람은 각자 폰에 깔아서 실제로 뜨개하며 고쳐 나가는 것이다.

Claude Code가 기능 구현 → eas update 로 무선 배포 (1~2분) → 하은 iPhone / 다희 Android 에 최신 버전 → 실제 편물을 기록하며 사용 → 불편함 · 버그 → GitHub Issue → 다시 위로
주체담당
Claude Code화면 · 로직 · 데이터베이스 · 테스트 코드
하은기획 판단, 테스트 설계, iPhone 검증, 콘솔 작업
다희기획 판단, 테스트 설계, Android 검증

첫 목표는 완성이 아니라 "손에 쥐어지는 것"이다. 1주차 안에 촬영 → 저장 → 목록이 폰에서 돌아가게 만든다. 서버도 로그인도 영상도 그 다음이다.

01환경 준비

1-1지금 뭐가 있는지 확인
터미널
node --version
git --version
xcodebuild -version
claude --version

없다고 나오는 것만 아래에서 설치한다.

1-2Homebrew · Node
Homebrew가 없을 때만
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
Node · ffmpeg · gh
brew install node ffmpeg gh

ffmpeg는 나중에 영상 검증에, gh는 저장소 초대에 쓴다. 지금 같이 깔아두면 편하다.

1-3Xcode — 지금 걸어두고 다른 걸 한다

App Store에서 Xcode 설치. 15GB가 넘어서 오래 걸린다. 다운로드를 먼저 시작해두고 아래 단계를 진행한다. 설치 후 한 번 실행해서 추가 컴포넌트까지 받아야 한다.

커맨드라인 도구
sudo xcode-select --install

Xcode는 3장(첫 실행)부터 필요하다. 2장까지는 없어도 진행된다.

1-4Claude Code
네이티브 설치 (권장)
curl -fsSL https://claude.ai/install.sh | bash

설치 후 새 터미널 창을 열어야 경로가 잡힌다. macOS 13 이상 필요.

완료 기준 — 새 터미널에서 claude --version이 버전을 출력한다

02저장소 셋업

2-1클론
터미널
mkdir -p ~/Claude/Projects
cd ~/Claude/Projects
git clone https://github.com/uhaeun/Knitting.git
cd Knitting

경로에 한글이나 공백이 없어야 한다. iOS 빌드에서 문제를 일으킨다.

2-2Expo 프로젝트 생성
터미널
npx create-expo-app@latest . --template default

.git이 이미 있다는 경고가 나올 수 있다. 진행한다.

2-3패키지 설치
터미널
npx expo install \
  expo-camera expo-image expo-image-manipulator expo-media-library \
  expo-sharing expo-asset expo-dev-client expo-updates \
  expo-build-properties expo-sqlite expo-file-system

npm i @tanstack/react-query zustand @shopify/react-native-skia

Supabase는 아직 설치하지 않는다. 1주차는 로컬 저장만 쓴다.

2-4app.json 수정

expo.plugins 배열에 추가한다.

app.json
["expo-build-properties", {
  "android": {
    "compileSdkVersion": 36,
    "targetSdkVersion": 36,
    "buildToolsVersion": "36.0.0"
  }
}]

같은 파일의 expo.name을 Knitting, expo.slug를 knitting으로 맞춘다. Android는 Play 신규 앱 요건상 API 36이 필수다.

2-5문서와 스파이크 파일 배치
다운로드 경로는 본인 것으로 수정
SPIKE=~/Downloads/spike-video-encoder

mkdir -p modules docs
cp -R $SPIKE/modules/video-encoder ./modules/
cp -R $SPIKE/scripts ./
cp $SPIKE/docs/spike-video-encoding.md ./docs/
cp $SPIKE/app/spike.tsx ./app/

# 문서들 (다운로드한 위치에서)
cp ~/Downloads/CLAUDE.md ./
cp ~/Downloads/닛팅_설계도_v1.1.html ./docs/
cp ~/Downloads/닛팅_진행가이드.html ./docs/
cp ~/Downloads/닛팅_디자인브리프.html ./docs/

find modules scripts docs CLAUDE.md app/spike.tsx -type f

CLAUDE.md가 가장 중요하다. Claude Code가 매 세션 읽는 규칙 파일이다. 이게 없으면 Supabase를 자꾸 붙이려 하고, 제거한 단수 카운터를 되살려낸다.

2-6EAS 설정
터미널
npm i -g eas-cli
eas login
eas build:configure
eas update:configure

eas update:configure를 빠뜨리지 않는다. 코드 수정을 빌드 없이 두 사람 폰에 내리는 통로다. 이게 없으면 매번 20분짜리 빌드를 돌려야 해서 반복 개선이 성립하지 않는다.

2-7커밋 · 푸시
터미널
git add -A
git commit -m "chore: Expo 프로젝트 초기화 + 설계 문서 + 영상 스파이크"
git push origin main
완료 기준 — GitHub 웹에서 파일이 보이고, CLAUDE.md가 저장소 첫 화면에 렌더링된다

03첫 실행 — 오늘의 진짜 성과

여기까지 오면 iPhone에 빈 앱이 뜬다. 기능은 없지만 파이프라인이 살아 있다는 신호라서 확인하고 가는 게 좋다.

3-1iPhone 연결하고 로컬 빌드

USB로 iPhone을 맥에 연결하고 "이 컴퓨터를 신뢰" 승인.

터미널
npx expo run:ios --device

기기 목록이 뜨면 본인 iPhone을 고른다. 첫 실행은 5~10분 걸린다.

서명 오류가 나면 Xcode로 ios/ 폴더를 열고 Signing & Capabilities 탭에서 Team을 본인 Apple ID의 Personal Team으로 지정한 뒤 다시 시도한다. Bundle Identifier가 중복이라는 오류면 뒤에 아무 문자나 붙여 고유하게 만든다.

무료 계정은 7일 후 만료된다. 앱이 갑자기 안 열리면 이것 때문이다. 그래서 오늘 Apple Developer Program을 신청한다(4장).

3-2Android 빌드 걸어두기
터미널
eas build --profile development --platform android

클라우드에서 빌드되고 끝나면 링크가 나온다. 그 링크를 다희 매니저님께 보내면 폰에서 바로 설치된다. 15~20분 걸리니 걸어두고 다른 걸 한다.

완료 기준 — 내 iPhone에 Knitting 앱 아이콘이 생기고 열리면 성공. 화면은 Expo 기본 화면이다

051주차 개발

셋업이 끝나면 여기부터 Claude Code가 일한다. 순서가 중요하다.

순서

#작업비고
1Claude Design으로 화면 4개 시안반나절. 디자인 브리프 문서 참조
2디자인 토큰 + 공통 컴포넌트화면보다 먼저. 이유는 아래
3로컬 저장 계층 (SQLite + 파일)repository 패턴으로
4편물 목록 + 만들기 시트
5촬영 화면 + 고스트 레이어이 앱의 핵심
6타임라인
7폰에 배포 → 도그푸딩 시작

토큰을 화면보다 먼저 만드는 이유 — 화면에 색과 간격을 직접 써두면 나중에 하나 바꿀 때 모든 화면을 열어야 한다. 토큰을 먼저 두면 한 곳만 고쳐도 전체가 따라 바뀐다. 지금 만드는 비용은 파일 하나다.

Claude Code 시작 프롬프트

저장소 폴더에서 claude 실행 후 붙여넣기
CLAUDE.md를 먼저 읽고, docs/닛팅_설계도_v1.1.html 의 데이터 모델과 화면 구조를 참고해줘.

지금은 1주차야. 로컬 저장만 쓰고 Supabase·로그인·피드·영상은 만들지 않아.

이번 작업 목표는 촬영 → 로컬 저장 → 목록·타임라인이 실기기에서 동작하는 것이야.

작업 순서는 이렇게 가줘. 한 단계씩, 각 단계가 끝나면 멈추고 확인받아줘.

1. src/shared/ui/tokens.ts — 디자인 토큰 (값은 내가 줄게)
2. src/shared/ui/ — 공통 컴포넌트 (버튼, 편물 카드, 빈 상태, 하단 시트)
3. 로컬 저장 계층 — expo-sqlite + expo-file-system.
   테이블은 projects, posts 두 개. 컬럼은 설계도 3장을 따르되 소셜 관련 컬럼은 빼줘.
   데이터 접근은 src/features/*/repository.ts 에만 두고 화면에서 직접 DB를 만지지 않게 해줘.
4. 편물 목록 화면 + 편물 만들기 시트
5. 촬영 화면 — 고스트 레이어(끔/30%/60%), 3x3 격자, 1:1 고정, 저장 파이프라인
6. 타임라인 화면

먼저 1번만 해줘. 시작하기 전에 무엇을 만들지 요약해서 보여주고.

2번 토큰 값은 Claude Design 결과에서 나온 목록을 붙여넣는다.

1주차 완료 기준

  • 편물을 만들고 목록에서 볼 수 있다
  • 촬영하면 사진이 저장되고 타임라인에 나타난다
  • 두 번째 촬영부터 직전 사진이 반투명하게 겹쳐 보인다
  • 투명도 세 단계와 격자 토글이 동작한다
  • 앱을 껐다 켜도 데이터가 남아 있다
  • 카메라 권한을 거부해도 앱이 죽지 않고 안내가 뜬다
  • 편물이 하나도 없을 때 빈 화면 안내가 나온다
  • 하은 iPhone과 다희 Android 양쪽에서 위가 전부 확인된다

06일상 루틴

코드를 고친 뒤 폰에 반영

TypeScript만 바뀐 경우 — 대부분
eas update --branch development --message "촬영 화면 고스트 투명도 조정"

1~2분이면 배포된다. 폰에서 앱을 껐다 켜면 최신 버전이 된다. 패키지를 새로 설치했거나 네이티브 코드가 바뀐 경우에만 eas build를 다시 돌린다.

매일

  • 실제 편물을 이 앱으로 한 장 이상 촬영한다
  • 불편했던 순간을 이슈로 남긴다. "오늘 찍기 귀찮았다"가 버그보다 값진 피드백이다

07이후 일정

시점내용끝났다는 신호

3주차Supabase 전환 — 계정, 데이터베이스, 사진 업로드기기 바꿔도 데이터가 따라옴
